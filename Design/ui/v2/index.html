Design Thesis

用户打开这个应用时，只问一个问题：
「我现在能拔了吗？」

旧版界面把「磁盘名 / 容量 / 进度条 / 占用进程 / 推出按钮」平铺成五层等权重的信息， 用户必须读完整行才能做出判断。v2 把信息按判定 → 身份 → 证据 → 动作 重新分层：先给结论，再给理由，最后给动作。

强调色
判定优先
每块盘的第一视觉权重给「能不能拔」这个结论，而不是磁盘名。 结论用图标 + 文字 + 颜色三重编码，扫视即可完成判断。
证据前置
「是谁占着」是本应用存在的理由，所以它从卡片底部的小标签升格为独立证据区， 用琥珀底色承载，并显示真实应用图标而不是进程名。
动作随状态变形
空闲时是强调色「推出」，被占用时变成红色「关闭并推出」。 破坏性在按钮本身就可见，不必点完才知道。

色彩 Color

全部取自 Apple 系统色，保证与 macOS 原生控件同源。语义色只承担一种含义： 琥珀 = 被占用，红色 = 破坏性，绿色 = 可安全操作。

无障碍 Accessibility

目标是 WCAG 2.1 AA。以下每一条都能在实现中被检验。

必须做到

  • 正文对比度 ≥ 4.5:1，非文本控件 ≥ 3:1。已核对：琥珀文字 #B25000 4.65:1、成功文字 #1E7A38 4.94:1、危险文字 #C1190F 5.1:1。
  • 状态不靠颜色单独表达。「被占用」同时有：左侧琥珀条 + 警告图标 + 文字结论 + 红色按钮，四重冗余。
  • 键盘可达。面板内所有交互元素可按 Tab 遍历，焦点环 2px 且仅在 :focus-visible 时出现。
  • 点击目标 ≥ 26 × 26，主要动作 ≥ 30 高。
  • 尊重「减弱动态效果」。prefers-reduced-motion 下所有过渡降为 0。
  • 文字放大 200% 不破版。所有容器用内边距而非固定高度约束。

VoiceOver 三个易错点

  • 行内按钮必须独立可访问。磁盘行合并标签时只合并「名称 + 容量」；把整行 combine 会把推出按钮一起吞进去，结果是「能读不能点」。
  • 按钮标签必须带磁盘名。「推出 Samsung T7」而非「推出」——多块盘时一串同名按钮毫无区分度。
  • 菜单栏自定义视图不会自动获得可访问性。NSMenuItem.view 一旦设置，系统不再提供默认支持，必须显式设置 role 与 label，装饰图标要 accessibilityHidden(true)。
